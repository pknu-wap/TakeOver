# 프롤로그·튜토리얼 제작 안내

## 실행

MainMenu 씬에서 **새 게임**을 누르면 암전 → 과거 프롤로그 → 호텔의 윤하진 → 미래건설 튜토리얼 → 자유 진행으로 이어진다. Game 씬을 직접 실행하면 일반 개발 경로로 진입한다.

대사는 대화창 또는 계속 버튼을 클릭해서 진행한다. 선택지가 있는 장면은 선택 → 주인공 답변 → NPC 답변 순서다. 전환 중 연속 클릭과 중복 선택은 차단한다.

## 도입부 스킵 — 2026-11-10

타이틀 맨 아래의 **튜토리얼을 스킵하고 새 게임 시작**은 기본 꺼짐이며 타이틀로 돌아오면 다시 꺼진다. 체크한 뒤 새 게임을 누르면 시작 스토리와 튜토리얼 화면을 생략하고 도입부 직후의 상태로 시작한다. 미래건설 1주를 기존 거래 시스템으로 실제 매수하고, 기존 턴 시스템으로 하루를 종료하며, 자금·기업 이력·날짜·AP·관계·Memory를 정상 진행과 동일하게 반영한다.

전체 스킵의 기본 선택은 서지아 **자금 상황 확인**, 강준혁 **장기 참여 검토**, 박도식 **작업량·일정부터 확인**이다. 이는 각 선택 장면의 `skipDefaultChoice = 0`이며 SO에서 제작자가 변경할 수 있다. 플레이어에게 추가 선택 메뉴나 별도 보상을 제공하지 않는다.

대화창 왼쪽 위의 **스킵**은 암전 후 다음 미응답 선택지로 이동하고 페이드인한다. 선택지를 자동으로 고르지 않는다. 선택지에서 스킵 버튼은 표시하되 비활성 상태이며, 답변을 고르면 다시 사용할 수 있다. 선택 후 응답 대사를 생략해도 이미 반영한 관계·Memory를 재적용하지 않는다. 사이에 있는 튜토리얼 매수·하루 종료는 공용 게임 경로로 필요한 횟수만 처리한다. 뒤에 선택지가 더 없으면 남은 도입부를 마치고 자유 진행으로 복귀한다. 거래 실패 시에는 해당 조작 단계에 머물러 실제 성공 없이 완료 상태를 만들지 않는다.

가족이 피해를 보는 **마지막 납품·제안서·빈자리** 장면만 `showPlayer = false`로 설정했다. 주인공 대사와 가족·그룹 담당자의 대사에서도 성인 정장 스탠딩을 표시하지 않는다. 이후 성인 시기의 스탠딩은 기존 규칙대로 유지한다.

## 일반 이벤트 대화 스킵 — 2026-11-10

기존 7개 일반 이벤트의 협상 대화에도 왼쪽 위 **스킵**을 표시한다. 일반 이벤트의 첫 질문은 선택지가 즉시 함께 표시되는 구조이므로 이때는 버튼이 비활성 상태다. 미응답 선택지를 자동으로 고르지 않는다.

주가조작 제안처럼 다음 회사 선택으로 이어지는 응답 대화는 스킵 시 암전 → 회사 질문/선택지 준비 → 페이드인 순서로 넘긴다. 마지막 선택 이후 더 이상 선택지가 없으면 암전 중 대화를 닫고 일반 화면으로 페이드인한다. 정상 진행의 응답 연출과 닫기 버튼도 유지한다.

스킵은 이미 확정된 효과를 다시 호출하지 않는다. 기존 EventSystemController가 AP·선택 이력·현금/주식 효과·NPC 관계/기억을 처리하며, 스킵은 화면 전환과 기존 다음 단계/종료 콜백만 수행한다. 전환 중 연속 스킵을 차단하고, 외부 닫기·씬 전환 시 대기 중인 전환을 취소한다.

검증은 `EventDialogueSkipVerification.Run`: 7개 이벤트/17개 선택지를 정상 진행과 각각 비교하고 전체 게임 상태가 같은지 검사한다. 결과 및 최신 실행 파일은 workspace `QA_EventDialogueSkip/RESULT_KO.md`, `QA_EventDialogueSkip/Build/TakeOver.exe`다.

## 빌드 경고 수정 — 2026-11-10

- `NotoSansKR-Regular SDF.asset`: Dynamic·멀티 아틀라스를 유지하고 `Clear Dynamic Data On Build`만 끈다. 빌드 도중 TMP 전처리기가 글자/아틀라스 데이터를 다시 변경하는 경로를 제거했다. 실제 Play 검사에서 한글 600자의 추가와 여러 아틀라스로의 확장을 확인했다.
- `UnityConnectSettings.asset`: 기존 Cloud Diagnostics Reporting은 이미 꺼져 있었다. 남아 있던 `InsightsSettings.m_EngineDiagnosticsEnabled`도 꺼서 미사용 Cloud 심볼 업로드 경로가 실행되지 않도록 했다. 인증을 위조하거나 경고 메시지를 필터링하지 않는다.
- 이번 최종 결과와 실행 파일은 workspace `QA_StorySkip/RESULT_KO.md`, `QA_StorySkip/Build/TakeOver.exe`를 확인한다.

## 제작 데이터

- `Data/IntroSequence.asset`: 93개 진행 항목. 각 항목의 배경, 장면명, 화자 종류, NPC ID, 대사, 선택지, 실제 조작 목표를 Inspector에서 편집한다.
- `Scripts/StorySequence.cs`: 데이터 계약. `Narration`은 이름과 인물 이미지를 숨기고 대화창 중앙에 정렬한다. 기존 이벤트 구도에 맞춰 `Player`는 오른쪽, `Npc`와 전화 등 `UnregisteredVoice`는 왼쪽에 정렬한다.
- 기존 인물의 표시 이름·직책·스탠딩은 `NpcDefinition`에서 조회한다. 장면 데이터에 복사하지 않는다. 미정인 가족·직원·그룹 인물은 표시용 호칭만 사용하며 새 NPC ID를 만들지 않는다.
- 스탠딩은 비율을 유지해 좌우 하단에 배치하고, 발화자와 청자의 밝기를 구분한다. 배경이 바뀌는 장면은 암전 후 교체하고, 같은 장면의 대사는 짧게 전환한다. 전환 시간은 sequence의 fadeSeconds로 편집한다.
- `Resources/Story/Intro.prefab`: 새 게임에서만 생성하는 진행기. Game 씬에 추가 배치할 필요가 없다.

일상적인 편집은 SO를 수정한다. `TakeOver > Story > Rebuild Approved Intro and Rivals`는 최초 제작용 AuthoringData.json으로 SO를 다시 생성하므로, 이후 수동 편집한 내용을 덮어쓴다. 자동 실행되는 메뉴가 아니다.

## 실제 게임 연결

도시맵에서 미래건설 선택 → 회사 정보·실제 자금과 주가 안내 → 실제 1주 이상 매수 → 강준혁 면담·인물 정보 → 박도식 현장 대화·기억 확인 → 기존 하루 종료 버튼 → 다음 회의 예고와 자유 진행.

매수는 기존 상세 패널과 ShareTradingSystem을 사용한다. 취소·잔액 부족·잘못된 수량에서는 진행하지 않는다. 성공 시 보유 주식 증가와 실제 현금 차감을 확인하며 연속 매수로 여러 번 처리되지 않게 한다. 주식 매수와 경영권 취득, 회사 운영자금 공급을 구분해 설명한다. 선택지의 효과는 기존 NPC 채널·처리기·기억 서비스에 전달한다.

컷신과 인물 확인 중에는 게임 뒤쪽의 클릭, 거래, 일반 이벤트 진입, 임의 턴 진행을 차단한다. 조작 단계는 금색 테두리 영역을 사용할 수 있다. 마지막 하루 종료도 기존 GameTurnClock을 딱 한 번 진행한다. 도입부의 대사·페이드·선택 자체로 AP와 날짜를 소비하지 않으며, 거래·하루 종료는 기존 게임 규칙을 따른다.

세 가지 대화에는 총 9개의 선택 결과가 있다. 새 결과는 Custom Memory로 별도 기록한다. 고용 유지 약속은 약속으로 기록하며 이미 회사를 구했거나 약속을 이행했다고 분류하지 않는다. 기록의 관계 수치는 초기 튜토리얼 밸런스이며 기존 이벤트 선택지의 기본값은 유지한다. Memory는 기존 저장·턴 만료 규칙을 따른다. 계약 이행·엔딩 판정과 도입부 중간 저장/재개는 이번 진행기의 기능 범위에 포함되지 않는다.

## 대립기업

### 인물 서사 확장 — 2026-11-10

신규 16명의 성격·행동·선호/기피·역할을 개편하고, 별도의 `NpcDefinition.storyDesign`에 개인 목표·충성 이유·내적 모순·견제 방식·협조 계기·대가·협조 한계·제공 정보 범위·거절선·재대립 조건·초기/중반/최종 등장 흐름을 기록했다. Inspector의 **메인 스토리 설계 · 제작자 전용**에서 편집한다. 이 제작용 조건은 기본 인물 정보창에 표시하지 않는다.

김성호·오진우·서유진·김서후는 끝까지 그룹 측에 남는 인물이다. 정유라 등 거래형 인물의 정보 제공은 특정 계약에 한정되며 영구적 아군화가 아니다. 실무자의 제한 협조와 회사 전체의 진영 전환도 구분한다. 상세 인물표와 서사는 `RIVAL_CHARACTER_DESIGN_KO.md`에 있다.

회사 SO의 `affiliationKind`, `loyaltyStructure`, `cooperationBoundaries`는 회사 관계와 권한의 경계를 정리한 제작 데이터다. 신성개발의 정확한 지분 구조는 미정으로 유지한다. 서사 입장이나 신뢰 수치만으로 자동 배신·정보 제공을 실행하지 않으며, 실제 메인 스토리 이벤트는 이 설계에 맞춰 별도 연결한다. 기존 Memory 보너스·사건 효과·NPC ID·스탠딩·기업 재무는 유지했다.

기존 회사 4곳을 유지하고 회사 5곳과 인물 16명을 추가했다. 총 회사 9곳, NPC 30명, CEO 9명이다. 새 인물의 원화는 아직 없으며 기존 인물 정보창의 공용 실루엣으로 표시한다.

`Data/Rivals/*.asset`은 회사 SO·소속 NPC SO, 그룹과의 관계, 견제 수단, 내부 갈등과 협상 여지를 담는다. 신성개발의 정확한 소유 구조와 최종보스 이름은 미정으로 유지했다. 각 NPC SO에는 성격·행동 양식·게임 역할·선호/기피와 개별 Memory 보너스가 있다. MemoryOnly, 공통 배율 꺼짐, 두려움·의존도 추가 증폭 제외 정책을 유지한다.

회사 데이터는 기존 Companies·Marketdata와 지도·회사 목록에 등록했다. 기존 회사별 CEO 이벤트와 구조조정 이벤트에도 신규 회사의 화자·대상을 추가해 다른 회사 NPC에게 결과가 적용되지 않도록 기존 회사 필터를 사용한다. 기존 대상의 선택지·수치·반응은 유지한다.

새 회사의 초기 재무 수치는 플레이 가능한 임시값이며 RivalCompanyDefinition의 provisionalFinancials에 표시한다. 견제 수단과 이탈 조건은 제작용 설정 데이터다. 자동 지분 선점·대출·개발권·출시 경쟁을 처리하는 별도 전략 AI는 이 데이터 등록으로 구현된 것이 아니다.

## 검증

- `TakeOver > Story > Verify New Game in Play Mode`: MainMenu 새 게임부터 전체 대본과 실제 조작, 일반 이벤트 복귀, Game 직접 진입을 검증하고 workspace의 QA_Story에 캡처·결과를 기록한다.

- `TakeOver > NPC > Verify Event Connection`: 실제 이벤트 선택부터 공용 NPC 처리기까지 검증.

세부 실행 결과와 검증 한계는 workspace `QA_Story/RESULT_KO.md`를 확인한다.
