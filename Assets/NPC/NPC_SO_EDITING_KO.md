# NPC SO 개별 정보 편집

`Assets/NPC/Data/Profiles/`의 NPC 에셋을 선택해 Inspector에서 편집한다. 인물마다 자신의 소개·이미지·호불호·기본 배율·항목별 보너스를 보관하며, 다른 인물의 SO와 값을 공유하지 않는다.

## 가장 간단한 설정

현재 14명과 신규 양식은 **보너스 기준 = 기억 (Memory)만**이다. 행동별 분류와 보너스는 계산에서 제외하며, Memory별 개별 배율을 사용한다. 캐릭터별 현재 수치와 근거는 [NPC_MEMORY_PREFERENCES_KO.md](NPC_MEMORY_PREFERENCES_KO.md)를 따른다.

1. **소개 · 소속 · 이미지**에서 이름, 소속, 표시 직책, 성격·가치관, 게임 내 역할과 스탠딩을 편집한다.
2. **이 NPC의 기본 호불호 보너스**에서 보너스 기준, 기본 보너스 사용 여부와 선호·불호 배율을 설정한다. **기억만**은 actionId와 관계없이 Memory 설정을 사용한다. **행동 우선 · 기억 대체**를 선택하면 기존 행동 우선 기능을 사용할 수 있다. 기본 배율은 신뢰·존중·적대감·관심에 적용하며, **적용 항목 직접 지정**으로 필요한 관계 항목만 선택할 수 있다.
3. **행동별 호불호** 또는 **기억 유형별 호불호** 목록의 `+`로 항목을 추가하고 선호/불호와 이유를 입력한다. 행동 ID는 이벤트가 전달하는 `actionId`와 정확히 같아야 한다. 예: `GoodFaith`, `ClearFundingPlan`, `FinancialMisrepresentation`. 임의의 새 행동 ID는 이벤트에서 같은 값을 전달해야 작동한다.
4. 대부분의 항목은 **이 NPC의 기본값 사용**으로 둔다. 유난히 중요하거나 별도 반응이 필요한 항목만 **이 항목만 개별 설정**으로 바꾼다.
5. **호불호 계산 미리보기**에서 행동 ID, 결과 기억 유형과 입력 변화량을 넣어 최종 수치를 확인한다. 미리보기는 SO와 실제 관계·기억을 바꾸지 않는다.

새 항목은 이전 항목의 행동 ID·개별 보너스를 복제하지 않는다. 기억 항목은 아직 쓰지 않은 유형으로 추가된다. 목록 순서 변경·삭제·실행 취소와 여러 에셋의 공통 값 편집을 지원한다. 계산 미리보기는 에셋 하나를 선택했을 때 제공한다.

## 항목별 보너스 방식

| 방식 | 작동 |
|---|---|
| 이 NPC의 기본값 사용 | 해당 SO의 기본 활성 설정·선호/불호 배율·관계 항목을 사용한다. 다른 NPC의 기본값은 참조하지 않는다. |
| 이 항목만 개별 설정 | 이 항목의 배율·적용 관계 항목·고정 변화량을 사용한다. NPC 기본 보너스가 꺼져 있어도 적용된다. |
| 이 항목은 보너스 없음 | 선호/불호 분류는 남기고 배율·추가 보너스를 적용하지 않는다. 기억 선호로 대신 적용하지도 않는다. 사건 기본 변화는 그대로 적용된다. |

**개별 배율**은 1 이상의 값이다. 1이면 증폭하지 않는다. **배율 적용 항목**은 6개 관계 중 선택할 수 있으며 아무 항목도 선택하지 않을 수도 있다. **고정 변화량**은 배율 처리 후 더하며, 입력한 부호 그대로 적용한다. 불호라고 해서 고정 변화량의 부호를 자동으로 뒤집지 않는다.

배율의 호의 방향은 신뢰·존중·의존도·관심 증가, 두려움·적대감 감소다. 선호는 호의 방향의 입력만, 불호는 반대 방향의 입력만 증폭한다. 기본 설정은 기존처럼 두려움·의존도를 제외한다. 이 방향과 관계없이 원하는 반응은 6축 고정 변화량으로 지정할 수 있다.

예를 들어 같은 `GoodFaith` 행동의 기본 신뢰 변화가 +4일 때, A의 항목을 **선호 / 개별 설정 / 배율 2 / 신뢰 선택 / 고정 신뢰 +1**로 두면 +9가 된다. B를 **선호 / 개별 설정 / 배율 1.25 / 신뢰 선택 / 고정 신뢰 -1**로 두면 +4가 된다. 이는 편집 방법을 설명하는 예시이며 기존 NPC의 밸런스에 일괄 적용하지 않았다.

## 적용 순서와 기록

1. 사건 공통 결과 또는 대상 NPC별 사건 결과를 선택한다.
2. **사건 기본 변화에 더할 인물별 보정**의 전체 사건 보정과 해당 기억 유형 보정을 더한다.
3. **기억만**이면 결과 Memory의 선호/불호만 사용한다. **행동 우선 · 기억 대체**이면 행동 ID의 명시적 선호/불호를 먼저 쓰고, 행동이 없거나 **미지정**일 때만 결과 기억 유형을 사용한다. 두 보너스를 중복 적용하지 않는다.
4. 선택된 항목의 보너스 방식에 따라 배율을 적용하고 개별 고정 변화량을 더한다.
5. 실제 관계의 상한·하한을 적용하고 기억에 기록한다.

Inspector 미리보기는 3~4단계만 계산한다. 2단계의 고정 보정과 5단계의 누적 관계 한계는 미리보기 입력에 자동 반영하지 않는다.

기억에는 당시 적용한 배율, 개별 설정 여부, 고정 보너스와 실제 적용량을 저장한다. 저장 후 SO를 수정하더라도 과거 기억을 다시 계산하지 않는다. 기존 기억은 추가 정보가 없어도 읽을 수 있다.

## 데이터 유지와 검증

기존 NPC 14명의 ID·GUID·소개·이미지·행동 분류는 유지했다. Memory 호불호는 캐릭터별 조정표에 따라 변경했다. 새 개별 보너스 설정이 없는 항목은 해당 NPC의 기본 설정을 사용한다. 등록 데이터의 ID 규칙은 `Docs/ID_CONVENTIONS_KO.md`를 따른다. 표시 이름을 바꾸려고 NPC ID를 함께 바꾸지 않는다.

입력 오류는 Inspector 아래에 표시한다. 빈/중복 행동 ID, 중복 기억 유형, 잘못된 분류·배율, NaN/무한대 관계 값 등을 확인한다. 오류가 있으면 계산 미리보기를 실행하지 않는다.

플레이는 시작할 때 SO를 복사해 사용한다. 에셋을 수정한 뒤 현재 플레이를 다시 시작하면 반영된다. 원본 SO는 관계·기억 저장 데이터로 사용하지 않는다.

검증 메뉴:

- `TakeOver > NPC > Verify Individual SO Settings`: SO별 보너스, Inspector 편집·Undo·그리기, 실제 런타임 기록·저장 및 기존 NPC Play 검증.
- `TakeOver > NPC > Verify Event Connection`: 실제 이벤트 선택부터 NPC 관계·기억까지 연결 검증.
