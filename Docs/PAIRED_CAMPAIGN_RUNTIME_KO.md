## 사건 묶음과 출현 잠금

성공 판정은 회사별 지분을 같은 시점에 확인한다. 묶음의 필수 카드만 동시에 보이고 읽는 순서는 자유다. 결과 대사까지 마친 사건을 완료로 기록한다. 첫 사건을 마치면 남은 카드 하나를 유지하고, 두 사건을 마친 뒤 일반 사건을 복원한다. 진행 중에는 거래와 날짜 진행이 잠긴다. 완료한 효과·NPC 기억·추첨을 다시 실행하지 않는다.

회사 첫 본편을 마치기 전에는 해당 회사 반복 서브가 잠긴다. 그린메일은 미래건설·동방물산이 33일차 공동 마무리 뒤, 하늘식품·한성공업이 41일차 공동 마무리 뒤에 열린다. 메인이 없는 신규 다섯 기업은 계속 잠긴다. 42일차 종합에는 새 지분 조건이 없어 앞선 그린메일과 충돌하지 않는다.

## 주인공 회사와 엔딩

공동출자로 시작한 소형 투자회사, 대표의 독립 운용과 단계별 사업 검토 전제를 프롤로그와 연락·보고 장면에 반영했다. 목표 미달은 대상 기업의 결정, 자기 회사의 사업·출자 검토, 청산·전환·대표 교체·매각, 주인공의 퇴장으로 이어진다. 후반 동시 실패는 시간 경과 뒤 주인공 회사가 APEX에 인수되는 결말이다.

실패 6개 기한과 미달 조합 14개에 고유 신호·회사별 실제 지분 스냅샷·엔딩 원고가 연결된다. 검은 화면 완료 후 기존 이벤트 UI를 복제한 공용 대화로 보여주며, 선택 효과를 실행하는 일반 사건으로 엔딩을 등록하지 않는다. 읽기 위치를 저장하고 끝에서는 재도전·타이틀을 제시한다. 현금이 남아 있는 상태를 임의로 개인 파산으로 쓰지 않는다.

회사의 출자·청산·대표 교체는 이번 서사의 전제와 종료 상태다. 별도의 주인공 법인 주식 거래, 외부 출자금 자동 지급, 숨은 대출·급여·임대료 차감 시스템을 추가한 것은 아니다. 서사 후일담으로 투자 대상 재무나 플레이어 잔액을 몰래 바꾸지 않는다. 초반은 계속 APEX의 개입 확인까지이며 과거 위반 실행·APEX 지시 입증은 중반에 남긴다.

## 저장·재도전·기존 저장

전체 저장은 v4를 유지하고 이벤트 섹션은 v6이다. 새 게임은 캠페인 버전 2, 이전 이벤트 v1~v5는 캠페인 버전 1로 보존한다. 이전 저장은 별도 레거시 스토리 DB의 기존 날짜·10% 조건·그린메일 완료 기준으로 이어간다. 새 30% 조건·추가 본편을 과거 저장에 소급하거나 과거 완료로 추정하지 않는다.

v6는 미완료 필수 사건 목록, 캠페인 실행 ID, 미달한 모든 목표와 실제 지분, 엔딩 신호와 읽기 위치를 보존한다. 묶음에서 하나를 마친 뒤 복원하면 남은 사건만 나온다. 잘못된 묶음·실패 신호·체크포인트를 적용 전에 거절한다.

자동 저장에 실패해 재기록할 사본이 남은 동안에는 날짜·거래·새 사건 진입·문서 결재와 읽음 처리를 막아 사본과 현재 상태가 어긋나지 않게 한다. 하루 마감에서는 저장 재시도를 문서·필수 사건 잠금보다 먼저 처리한다. 재시도는 저장 사본만 기록하고 날짜나 경제를 두 번 진행하지 않으며, 성공 후에도 원래의 문서·필수 사건 제한은 유지된다.

미션 준비 시작의 별도 저장은 2/7/15/23/29/34일차에 해당 연락·필수 장면과 튜토리얼을 마친 뒤 기록한다. 경로는 일반 저장 경로 아래 `checkpoints/<실행ID>/<미션ID>/progress.json`이며 해당 실행·미션의 준비 저장인지 검증한다. 최신 실패 자동 저장과 분리된다. 엔딩의 재도전은 준비 시점 전체 상태를 복원하고, 타이틀 이어하기는 최신 자동 저장을 복원한다. 구버전이나 정상적인 준비 저장이 없는 경우 재도전을 표시하지 않고 타이틀 복귀는 제공한다.

자동 검증은 `QA_PairedCampaign`의 격리 경로를 사용한다. 개인 진행 저장을 시험 대상으로 쓰지 않는다.
