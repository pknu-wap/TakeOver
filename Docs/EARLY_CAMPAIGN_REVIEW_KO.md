# 42일 캠페인 후속 작업 검토

> 커밋 시 완료 QA 폴더는 정리한다. 아래 로그·빌드 경로는 과거 출력 위치이며 결과는 [검증 기록 보존본](CAMPAIGN_VALIDATION_KO.md)에 남긴다. 내일 시작할 순서는 [다음 작업 인계](CAMPAIGN_HANDOFF_KO.md)를 따른다.

2026-11-18. [42일 진행·엔딩 안내](EARLY_CAMPAIGN_GUIDE_KO.md)를 문서화하면서 실행 데이터·저장 코드·기존 QA 증거를 다시 대조했다. 기존 Play 6,645 PASS와 빌드 콘텐츠 1,421 PASS는 이전 전체 검수 이력이며 이번 추가 검사 횟수와 구분한다.

## 이번에 발견해 보완한 문제

### 저장 재시도가 다른 날짜 잠금에 가로막힘

자동 저장 실패 사본이 남으면 이벤트 진입을 막는다. 그러나 기존 날짜 진행 경로는 문서형 `ITurnBlocker`와 필수 사건 검사를 먼저 만날 수 있었다. 그러면 ‘필수 처리를 하라’고 안내하면서 그 처리 화면은 저장 실패 때문에 열 수 없는 상태가 된다.

격리된 실제 19→20일차 진행에서 자동 저장 실패·필수 카드 2개·문서와 동일한 등록 경로의 턴 차단기를 조합해 재현했다. `QA_CampaignReview/before-fix.txt`에 수정 전 증거를 남겼다.

`GameTurnClock.AdvanceTurn()`에서 저장 복구를 다른 날짜 잠금보다 먼저 처리하도록 수정했다. 재기록에 성공해도 그 클릭으로 날짜를 넘기지 않는다. 이후 원래 문서·필수 사건 제한을 그대로 검사한다. 자동 저장뿐 아니라 준비 체크포인트만 쓰기에 실패한 경우도 같은 순서로 복구한다.

### 저장 실패 사본이 남아 있는 동안 문서 상태가 바뀜

거래·새 이벤트는 잠겨 있었지만 운영 문서의 결재·읽음 처리는 가능했다. 실시간 문서 상태가 이미 캡처한 저장 사본과 달라질 수 있었다. 등록된 배당 정책 문서와 읽기 전용 문서로 재현하고 `QA_CampaignReview/before-document-fix.txt`에 기록했다.

`DocumentInbox.Resolve()`와 `MarkRead()`도 저장 복구 전에는 상태를 바꾸지 않게 했다. 처리 시도에는 기존 안내 메시지를 사용하며 원본 UI 프리팹은 바꾸지 않았다.

## 현재 정책으로 유지하는 사항

- 새 42일 진행은 새 게임에 적용하고 이전 저장은 종전 29일 진행으로 유지한다. 이는 미완료 이행 작업이 아니라 강제 기한 실패와 그린메일 재매수 금지 충돌을 피하기 위한 호환 정책이다.
- 주인공 회사의 공동출자·사업 심사·대표 교체는 서사와 종료 상태로 구현됐다. 별도의 법인 주식 거래·숨은 대출·운영비 차감을 추가해야만 엔딩이 완성되는 것은 아니다.
- 반복 대본 27편 중 스트레스 추첨에서 26편이 관측됐다는 결과는 1편 미구현을 뜻하지 않는다. 모든 27편·75개 결과는 별도로 실행했다.
- 이번 재검수로 전체 시나리오를 모두 다시 플레이한 것으로 주장하지 않는다. 발견한 저장 경로와 그 회귀 검사를 추가하고, 나머지 전체 검수 이력은 기존 결과로 표시한다.
