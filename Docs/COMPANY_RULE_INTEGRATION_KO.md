# 회사 지표 PR 연동과 이벤트 저장 — 2026-11-11

## 적용 범위

스토리 분기와 NPC·회사 등록 구조는 변경하지 않는다. 회사 데이터 PR #35와 그 위에 쌓인 규칙 PR은 아직 머지되지 않은 선행 작업이다. 새 CompanyStat, 회사 상태, growthRate/initialEmployeeCount/dividendRatio, CompanyRuleRunner와 설정 SO는 이 브랜치에서 중복 작성하지 않는다.

현재 반영한 내용:

- 유료 이벤트는 선택 완료 기록·NPC 효과·현금 전달 전에 보유 현금을 확인한다. 부족하면 공용 안내를 표시하고 다른 답변을 선택할 수 있다. 이미 시작한 만남의 AP를 추가로 차감하거나 환불하지 않는다.
- EventSystemController는 전체 저장 계약에 참여한다. 전체/회사별 선택 결과, 발생 회사와 최초 발생일, 유효 기한 계산에 쓰는 날짜, 만료 후 재발생 가능일을 저장한다. 현재 구현에는 별도의 발생 횟수 카운터가 없으므로 새 규칙으로 추가하지 않는다.
- 미응답 면담 중 저장은 거부한다. 결과가 확정된 상태의 저장은 허용하며 로드 시 대화창은 닫힌 상태로 복원한다.
- NPC 관계·기억·현재 턴 및 AP도 같은 전체 저장에 포함한다. 기존 NPC 단독 저장 API는 유지한다.
- GameSaveManager는 Inspector에 명시한 순서 다음에 현재 로드된 씬의 ISaveParticipant를 ID 순서로 보충한다. 같은 컴포넌트는 중복 등록하지 않으며, 서로 다른 컴포넌트의 중복 saveId는 오류로 거부한다. 비활성 씬 컴포넌트도 포함하므로 테스트용 저장 컴포넌트를 게임 씬에 남겨 두지 않는다.
- 전체 파트의 검증 완료 뒤 적용한다. 이벤트 카드는 거래 파생 수치와 NPC 상태가 복원된 뒤 재구성한다. 로드는 추첨·AP 소모·턴 진행·이벤트 효과 지급을 하지 않는다.
- 상단 메뉴는 버튼 배열 위치와 DashboardTab 식별자를 분리한다. 새 탭을 삽입할 때 tabButtons와 tabKinds를 같은 순서로 지정한다. 운영 탭 화면 자체는 만들지 않는다.
- GameTurnClock에 ITurnAdvanceGuard 연결부를 추가한다. 문서 담당이 활성 컴포넌트에서 CanAdvanceTurn을 구현하고, 차단 시 OnTurnAdvanceBlocked에서 안내와 문서 화면 이동을 처리한다. 차단 판정은 턴·기억·AP·회사 규칙이 진행되기 전이다. 현재 문서 데이터나 운영 화면이 없으므로 마감 문서 기능이 완성된 것으로 안내하지 않는다.

## 저장 호환성

새 전체 저장은 trading/events/npc/action-points 파트를 포함한다. 필요한 파트가 없는 기존 전체 저장은 거부하며, 누락된 이벤트 완료 기록을 초기 상태로 채워 이미 지급한 보상을 다시 받을 수 있게 만들지 않는다. 기존 NPC 단독 JSON은 별도 API에서 계속 다룬다.

회사 수치 수를 검증하는 기존 stats.Count 검사는 유지한다. #35의 옛 수치 12개 저장 거부 문제는 해당 코드 머지 후에 실제 형식과 함께 해결해야 한다. 정의되지 않은 회사 상태를 보정하거나 저장 데이터를 추측해 변환하는 코드는 추가하지 않는다. 구 저장 지원 여부와 변환 기준이 확정되면 명시적인 버전 변환을 추가한다.

## 선행 PR 머지 시 필수 검증

1. CompanyState/TradingSaveData/TradingSaveAdapter 병합 시 새 회사 상태·수치와 greenmailBuyBlocked를 모두 보존한다. stats.Count와 enum 유효성 검사를 유지한다.
2. PR의 회사 4개뿐 아니라 이 브랜치에서 추가한 회사 에셋의 새 초기값과 규칙 대상 여부를 확인한다. 에셋을 Data/Company로 옮길 때 .meta GUID를 유지하고 직접 지정한 에셋 경로도 갱신한다.
3. 실적·직원 수 갱신 주기와 배당 지급 주기를 구별해 확인한다. 자료의 배당 10% 이상 조건 및 임시 13주 주기와 PR의 7턴 설명 중 실제 채택된 규칙을 대조한다. 설명만 보고 지급 조건을 임의로 바꾸지 않는다.
4. 회사 종류의 정본을 받은 뒤 스토리 기업의 인수 전 자동 폐지 예외가 적용되는지 확인한다. 임의로 이름이나 NPC 유무로 기업 종류를 추정하지 않는다.
5. 정리매매·상장폐지 시 매수 금지, 매도 허용 기간, 종료 후 지분 정리가 거래 경로에도 연결되는지 확인한다. 규칙 PR은 거래와 상태 표시 UI를 범위에서 제외했으므로 추가 연동이 필요할 수 있다.
6. ruleRunner가 중복 실행되지 않으며 이력 기록 전에 실행되는지, 모든 실행 프리팹의 설정 참조가 올바른지 확인한다. EventListener의 player가 null이면 Awake에서 Player를 찾는 기존 경로가 실제 씬에서도 성공해야 한다.
7. 실제 씬에서 7턴 경계 직전·직후 전체 저장/로드, 배당의 중복 지급 방지, 회사 상태와 영구 매수 금지의 보존을 검증한다. 새 경제 코드가 없는 현재 브랜치의 검증으로 대체할 수 없다.
8. 통합 후 HelpTopics의 실적·배당·회사 상태 설명을 실제 사용 가능한 규칙으로 갱신하고 필요한 화면 사진을 추가한다. 상태 표시 UI가 없는 경우 존재하지 않는 표시를 안내하지 않는다.
