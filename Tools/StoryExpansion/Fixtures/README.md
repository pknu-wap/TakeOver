# Campaign verification fixtures

These are synthetic saves generated by the automated campaign checks, not player progress. Keep them with the verification code so deleting disposable root `QA_*` folders does not break the next checkout's tests.

| File | Purpose |
|---|---|
| `legacy-v5-progress.json` | Whole-save v4/event v5 at day 221, completed original campaign; legacy migration checks |
| `completed-v6-progress.json` | Whole-save v4/event v6 at day 234; completed paired campaign and repeat stress state for carousel checks |
| `before-day-20.json` | Day 19 before the first two-company deadline |
| `before-day-40.json` | Day 39 before the final two-company deadline |
| `early-a2-start.json` | Day 29 mission preparation state for checkpoint-only storage failure checks |
| `early-b2-start.json` | Day 34 mission preparation checkpoint used by ending-button checks |

From the Unity project root, use these batch execute methods:

- `CampaignReviewVerification.RunAfterFix`: storage recovery and document mutation regression; creates `../QA_CampaignReview`.
- `CardQueueVerification.Run`: carousel, paired card layout, ending controls; creates `../QA_PairedCampaign`.
- `SessionSaveVerification.Run`: automatic saves, retry, continue and legacy sections.
- `CampaignIntegrationVerification.Run`: generates its own active run and per-deadline baselines, then verifies 42-day success/failure and repeatable outcomes; only the legacy migration input comes from this directory.

Normal tutorial/whole-skip comparison still runs `TakeOver.Story.Editor.StoryPlayVerification.RunSkipRegression` before `TakeOver.Story.Editor.StorySkipVerification.Run`, with the same `TAKEOVER_QA_OUTPUT` directory. The first step intentionally generates the comparison baseline.

Tests use isolated output paths. Generated logs, screenshots, builds and save copies remain disposable root QA outputs; they are not committed here.
